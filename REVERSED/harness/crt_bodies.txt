# Ghidra decompiled the *runtime's own* functions as ordinary `sub_XXXX` bodies, and those
# cannot run in a rebuild: they use the MSVC 6 FILE layout (0x0C = `_flag`, 0x10 = `_file`)
# and the 2001 CRT's `_iob` table and heap - none of which a modern `fopen` produces.  The
# game's first save write (`sub_41C050`) faults on exactly that: the reversed `fclose`
# writing through a FILE structure the rebuild never made.
#
# The bodies are therefore removed from *both* builds and harness/crt_aliases.c supplies the
# same names as calls into the modern CRT (the same decision already taken for _malloc,
# _strlen and the C++ runtime).  The names are the *call targets* IDA prints - `_fopen`,
# `_fwrite`, `_fclose` - mapped to the Ghidra body that implements them.

sub_562AEE       # _fopen   -> fopen
sub_562B75       # _fwrite  -> fwrite
sub_5628EB       # _fclose  -> fclose
sub_562717       # _sprintf -> vsprintf (via a variadic wrapper)
sub_56279D       # _strtok  -> strtok
